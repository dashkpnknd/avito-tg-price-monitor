# Avito Telegram Price Monitor

Сервис раз в час сверяет цену одного товара в трёх местах:

1. клиентской таблице;
2. соответствующей строке автозагрузки;
3. активном объявлении в профиле Авито.

Для проектов с обычной таблицей цен сервис на каждом запуске читает все листы, где есть колонка `Price`: при пустой колонке «ЛИСТ» в контрольной таблице так же работает скрипт `updatePricesFromPriceToAvito`. Листы без `Price` пропускаются. Затем бот ищет строку по точным правилам этого скрипта: пустое значение не совпадает с непустым; для `AKB` действует обратная критичная проверка. Служебные колонки «Причина без цены», «Причина отсутствия цены», `Reason Without Price` и `Missing Price Reason` исключаются. Если есть несколько точных совпадений с ценой, используется первая строка в порядке листа, как в скрипте. Отдельные старые проекты с особой структурой прайса по-прежнему используют явно настроенные листы.

Если точного совпадения нет, бот самостоятельно проверяет эквивалентные значения товара: `1 ТБ` = `1024 ГБ`, `GB` = `ГБ`, известные варианты написания SIM и цвета, а также название модели с повтором бренда из колонки `Vendor`. Для листов с одними `Title` и `Price` он сравнивает названия без завершающих слов «Гарантия» и «Рассрочка»; комплектации вроде «Дисковод» остаются разными товарами. При этом должны совпасть **все** параметры клиента, а подходящая строка должна быть единственной. Если единственное различие — неопределённое значение SIM (`Не знаю`) с одной стороны, бот сопоставляет строку по остальным параметрам только при единственном кандидате. Два разных явно указанных варианта SIM не объединяются.

Бот также читает клиентские строки с пустой ценой, чтобы отличать существующий товар без текущей цены от отсутствующей строки. Точное совпадение со строкой без цены имеет приоритет перед приблизительным совпадением со строкой с ценой. Пока клиентская цена пустая, бот не заявляет о расхождении с ней; при этом он продолжает сравнивать цену автозагрузки с активным объявлением. Если уверенного сопоставления нет, бот записывает пример в журнал сервера и не отправляет уведомление о якобы отсутствующей строке или цене. Скрипт автообновления при этом не меняется.

Монитор проверяет только объявления, связанные со строками автозагрузки. Ручные б/у объявления не включаются: строки с состоянием «Удовлетворительное», «Хорошее» или «Отличное» игнорируются. Само по себе объявление, которое есть в профиле Авито, но отсутствует в автозагрузке, уведомление не вызывает.

Уведомление отправляется в Telegram, только если расхождение сохраняется 5 часов. Бот присылает полный отчёт по проекту. Если состав проблем меняется или проходит `NOTIFICATION_REPEAT_HOURS` (по умолчанию 5 часов), он отправляет новый отчёт и затем пытается удалить предыдущий. Если Telegram уже не разрешает удаление, старое сообщение остаётся без изменений. После исправления расхождений бот также только пытается удалить последнее уведомление.

## Подключение новых проектов через Telegram

В личном чате с ботом администратор отправляет `/start`, нажимает «Добавить проект» и последовательно передаёт название, две ссылки на таблицы и ключи Авито. Затем выбирает задержку и подтверждает подключение. Бот сохраняет проект на сервере и включает его в ближайшую часовую проверку. Добавлять проекты разрешено только Telegram ID из `TELEGRAM_ADMIN_USER_IDS`; это не даёт участникам общего чата увидеть ключи или подключить чужой проект.

## Что уже подтверждено для LimeStore Гатчина

- API-ключи Авито открывают профиль **Lime Store Гатчина** и список активных объявлений.
- В автозагрузке есть отдельные листы категорий, включая «Avito - Смарт-часы» и «Avito - Наушники».
- В клиентской таблице листы «Часы (авито)» и «Наушники (авито)» имеют поддерживаемую структуру `Title` + `Price`.
- Для телефонов в Гатчине подключен шаблонный лист «Телефоны (авито)». Этот проект использует отдельную настройку листов из-за формата исходного прайса.

## Настройка

```sh
cp .env.example .env
cp config.gatchina.example.json config.json
mkdir -p data
```

В `config.json` укажите ID клиентской таблицы в `client_spreadsheet_id` и ID автозагрузки в `autoload_spreadsheet_id`. Сервис сам найдёт вкладки с `Price` в клиентской таблице и вкладки с `Avito` или «Авито» в автозагрузке. В `.env` задайте Telegram и Avito ключи, а также `TELEGRAM_CHAT_ID`. Эти файлы игнорируются Git.

Для проверки без сообщений в Telegram:

```sh
DRY_RUN=true python -m app.main
```

Запуск на сервере:

```sh
docker compose up -d --build
docker compose logs -f
```

## Получение Telegram chat ID

После добавления бота в группу отправьте в неё команду `/start`. Затем получить `chat_id` можно запросом `getUpdates` Bot API. Значение обычно начинается с `-100` для супергруппы. Бот не получает обычные сообщения при включённом privacy mode, но команду `/start` получит.

## Безопасность

Не добавляйте в Git токен Telegram, Avito `Client Secret`, временный токен Авито или вебхук-секрет. Если секрет когда-либо был отправлен в переписку или сохранён в коде, замените его перед production-запуском.

## Роль проекта в системе

Сервис контролирует совпадение цены товара в клиентской Google Таблице, строке автозагрузки и активном объявлении Avito, затем сообщает о расхождениях в Telegram. Это проверка цен, отдельная от `avito-stats-bot`, который собирает статистику объявлений и отправляет отчёты.
